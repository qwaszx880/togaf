# Plain-language glossary

| Term | Practical meaning |
|---|---|
| Architecture Building Block (ABB) | A package describing required architecture capability, later realized by solutions |
| Architecture Contract | Agreement defining responsibilities, deliverables, quality, and implementation expectations |
| Architecture Development Method (ADM) | Iterative TOGAF method for developing, governing, and changing EA |
| Architecture principle | Enduring rule and rationale guiding decisions |
| Architecture Repository | Organized store for architecture and governance assets |
| Baseline Architecture | Relevant current-state description |
| Building block | Potentially reusable package of business, IT, or architecture capability |
| Capability | An ability an organization needs or possesses |
| Catalog | Artifact listing entities of one kind |
| Concern | A stakeholder interest relevant to the architecture |
| Content Metamodel | Definitions and relationships that structure architecture content |
| Deliverable | Formal, reviewed work product, often containing artifacts |
| Enterprise | A collection of organizations sharing goals, at the scope relevant to the work |
| Enterprise Architecture (EA) | Coherent practice/descriptions used to guide enterprise change toward outcomes |
| Enterprise Continuum | Classification lens from generic assets toward organization-specific assets |
| Gap | Difference identified between Baseline and Target |
| Governance | System of authority, accountability, control, and compliance |
| Matrix | Artifact showing relationships among entity types |
| Requirement | Statement of a needed outcome, capability, behavior, quality, or constraint |
| Roadmap | Time-oriented view of work packages, transitions, dependencies, and direction |
| Solution Building Block (SBB) | Solution component that realizes required capability |
| Stakeholder | Person, group, or organization with concerns about outcomes/architecture |
| Target Architecture | Intended future-state description |
| Transition Architecture | Formal intermediate state between Baseline and Target |
| View | Representation of architecture addressing related stakeholder concerns |
| Viewpoint | Conventions for constructing and using a view |
| Work Package | Bounded set of actions designed to achieve an outcome or address gaps |
