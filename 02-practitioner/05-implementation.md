# P5 — Implementing the architecture: Phases E, F, and G

## Outcomes

Translate gaps into solution directions and work packages, create a value/risk-aware migration plan, and govern implementation.

> **See it in practice:** Convert 18 gaps into [four work packages, transition states, and useful compliance evidence](../examples/practitioner/04-roadmap-and-governance.md).

| Phase | Key decision | Avoid |
|---|---|---|
| E — Opportunities & Solutions | What solution building blocks, work packages, and Transition Architectures make change achievable? | Treating every gap as a separate project |
| F — Migration Planning | Which initiatives happen when, considering value, cost, risk, dependencies, and resources? | Ranking on value alone |
| G — Implementation Governance | How will delivery demonstrate conformance and handle deviations? | Architects taking over project management |

## From gaps to roadmap

Consolidate related gaps, identify dependencies, and create work packages with outcomes. Transition Architectures describe meaningful interim states where a single jump is impractical. Phase F works with portfolio/project management to estimate and prioritize. The roadmap communicates sequence; the Implementation and Migration Plan provides actionable detail.

Phase G confirms resources/skills, guides implementation, performs compliance reviews, uses an Architecture Contract, and manages implementation-driven change through governance. Conformance is risk-based, not aesthetic similarity to diagrams.

## Exercise

Use the [roadmap template](../case-study/templates/roadmap.md). Sequence inventory data quality, reservation service, store process/pilot, and scaled rollout. State dependencies, value, risk, and a compliance checkpoint.

## Check

**Scenario:** A high-value work package depends on unresolved identity controls. Should it automatically rank first? **Answer:** No. Phase F balances value with dependency, risk, cost, and readiness; resolve or explicitly treat the constraint.
