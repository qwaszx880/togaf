# Practitioner example: build a decision-ready Architecture Vision

[Back to theory: Phase A](../../02-practitioner/03-phase-a.md)

## Situation

The sponsor says, “Launch click-and-collect this year.” That is direction, not yet a decision-ready vision.

## Elicitation trail

| Question | Discovered fact | Phase A consequence |
|---|---|---|
| What failure are we fixing? | 12% of collection orders are cancelled. | baseline measure and value hypothesis |
| Who experiences change? | customers, store staff, regional operations, security, product teams | stakeholder/concern map |
| What outcome is credible? | below 4% cancellation in 60 pilot stores | scope and success measure |
| What limits us? | nine months; uneven event support; peak season | assumptions, risk, roadmap constraint |
| Who can authorize? | board sponsor funds; regions own local operations | governance and decision rights |

## Vision statement

“Northstar will enable customers in 60 pilot stores to reserve available products online and receive confirmation within two minutes, reducing cancellations below 4%, through a consistent fulfillment capability and governed shared availability information while permitting bounded regional implementation.”

It names outcome, scope, customer experience, high-level direction, and federation. It deliberately does not select a vendor.

## Decision package

- **Included:** pilot journey, store fulfillment, availability/reservation information and services, enabling platform qualities.
- **Excluded:** home delivery, replenishment optimization, device refresh.
- **Risks:** semantics, store workload, integration feasibility, privacy.
- **Validation:** technical spike, store walkthroughs, security review.
- **Gate:** proceed only when sponsor accepts outcome/scope, regions accept rights, and spike supports feasibility.

## Try it first

Which belongs later: detailed API schema, high-level application interaction, vendor contract, or value measure?

**Debrief:** detailed API schema belongs in delivery design; vendor contract follows an evidence-based selection/procurement path. High-level interaction and value measure help Phase A alignment.

## Learner variation

If the board mandates a named platform before Phase A, do not pretend the constraint does not exist. Record and test it against outcomes, risks, and principles; escalate evidence if it makes the vision infeasible.
